## Per-sample pipeline

1. XAPK → `unzip` to `extracted/<sample>/raw/bundle/` (mkdir parents first — `unzip -d` does not create nested paths).
2. Base APK (largest non-config) → `raw/app/`; arm config split merged for libs (GPay current, PhonePe 26.x).
3. `strings -a` per dex; classify npci-bearing dexes via `L(in|org|com).npci.*;` descriptor regex → `npci_classes`, `npci_dex_strings.txt`.
4. `jadx --single-class org.npci.upi.security.pinactivitycomponent.CLConstants` on the npci dex (note: CLConstants lives in `classes2.dex` for GPay, `classes.dex` for BHIM/PhonePe).
5. Full `jadx` of npci dexes → `jadx-full/` for structure reads (class trees, JS bridge, Lite helpers).
6. `libSecureComponent.so` → `sha256sum` + `strings` for feature flags; `cl_candidate_libs` detection by name.
7. Feature-marker matrix: 28 markers × all samples → `data/markers_matrix.csv`, evidence excerpts → `data/markers_evidence.json`. Marker hit counts are app+CL combined — treat as corroboration, use the npci-scoped dumps for CL claims.
8. `CLConstants` field list (269 fields, GPay 210) → `data/extracted/gpay-210.1.2/clconstants_fields.txt`.

## Known caveats

- PhonePe 25.x: CL re-namespaced into their own SDK → `npci_classes=0` by design; CL identity evidenced by surviving internals (`CL_VERSION`/`LITE_CL_VERSION`/`cl-messages` strings) and the frozen `2.3-v1.8` value.
- Marker counts include host-app strings; only Era/section claims cross-checked against npci-scoped dumps.
- BHIM 2.3.1 CL_VERSION is R8-inlined (source shows `null`); value not recoverable without smali const tracing.
- WhatsApp Pay, CRED, etc. not sampled — corpus is BHIM/GPay/PhonePe only.
- Tool versions: jadx 1.5.1 (GitHub release), apkeep (EFF), apktool, poppler `pdftotext`.
